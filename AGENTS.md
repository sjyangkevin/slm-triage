## Issues/PRs Triage Instructions
When evaluating newly opened issues and pull requests, use the following criteria.

### Issues

**Good Issues:**
- Clearly describe the problem or feature request.
- Include specific, minimal steps to reproduce for bug reports.
- Detail the expected vs actual behavior.
- Reference related issues or discussions when applicable.

**Bad Issues:**
- Provide vague descriptions ("It doesn't work", "Please fix").
- Lack steps to reproduce or stack traces for crash reports.
- Open duplicate issues that are already covered by existing open issues.
- Ask for support or configuration help without demonstrating a concrete bug.

### Pull Requests

**Good Pull Requests:**
- Reference an existing, reviewed Issue.
- Keep changes focused on the linked issue.
- Include or update automated tests for any code changes.
- Feature a clear title that summarizes the change (e.g., "Fix timeout in retry logic").
- Provide a description explaining *what* changed and *why*.

**Bad Pull Requests:**
- Submit code without an associated issue or clear context.
- Feature unchecked AI-generated code without thorough review and testing.
- Include massive refactoring with multiple unrelated features.
- Provide empty or single-sentence descriptions ("Fixed bug").
- Lack tests for new features or bug fixes.
