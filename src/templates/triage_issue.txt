=== EVALUATION CRITERIA ===
For Issues, evaluate the content by looking at the following aspects. Be reasonable and use common sense—simple bugs or feature requests require less exhaustive detail than complex ones.
1. Description: A clear description of the issue, what happened, and what should happen instead. Very vague descriptions should be penalized.
2. Reproducibility: How to reproduce the issue (e.g. package version, system OS, code snippets, screenshots). A good issue provides helpful clues; however, if the issue is straightforward, exhaustive details are not strictly required.
3. PR and Triage Status: Is there any PR open while the issue still needs triage? Look for tags like `needs-triage` or PR links. If it's pending triage but has a PR, it may need more context.
4. Context & Details: The description should provide enough overall context to be actionable for a maintainer.

Decision rules for Issues:
- Pass if: The issue meets at least half of the above criteria.
- Needs Details if: The issue does not meet half of the criteria. Request more details.
